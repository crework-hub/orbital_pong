# Telegram-бот для Orbital Pong (ЛР 3)

Бот-помощник для игры **Orbital Pong** (вариант 15). Игра остаётся в Pygame, а бот работает рядом: считает полёт мяча и разбирает файл рекордов, который пишет игра.

## Что делает бот

1. **Симуляция.** Принимает массу чёрной дыры и начальный вектор мяча (vx, vy), считает траекторию по формуле `F = G·M / d²`, рисует GIF через Pillow и присылает его с вердиктом: мяч **совершил оборот**, **упал в дыру** или **улетел**.
2. **Рекорды.** Принимает `records.csv` из игры, проверяет каждую строку и собирает общую таблицу лидеров (самые быстрые победы).
3. **Статистика.** Сколько запусков сделал пользователь, сколько раз был оборот, лучший угол.
4. **Уведомления.** Подписчики получают сообщение, когда кто-то загрузил новые рекорды. Админ может сделать свою рассылку.

Игра в чате не повторяется: в боте нет ракеток и счёта, он только считает физику и читает данные игры.

## Запуск

1. Создать бота в Telegram: написать `@BotFather`, команда `/newbot`, получить токен.
2. Установить зависимости (нужен Python 3.12 или новее):

```bash
cd py_bot
pip install -r requirements.txt
```

3. Скопировать `.env.example` в `.env` и вписать токен (`ADMIN_IDS` можно оставить пустым):

```
BOT_TOKEN=123456789:AA...
ADMIN_IDS=
```

4. Запустить (поллинг):

```bash
python bot.py
```

Без токена бот не стартует и пишет об этом. Файл `.env` в репозиторий не попадает (он в `.gitignore`).

## Как пользоваться

- `/start` — главное меню с кнопками, `/help` — справка, `/cancel` — отмена ввода.
- «🌀 Новая симуляция» → масса (например `6`) → вектор (например `3 1`). Приходит GIF и вердикт.
- «📤 Загрузить records.csv» → прислать файл. Бот ответит, сколько записей принято и какие строки отклонены.
- «🏆 Таблица лидеров», «📊 Моя статистика», «🔔 Уведомления».
- Для админа (id из `ADMIN_IDS`): `/log` — последние строки лога, `/broadcast текст` — рассылка подписчикам. Остальным бот отвечает «Нет прав».

## Как устроено

**Физика.** `simulation.py` считает по кадрам, как в игре: `F = G·M / d²`, ускорение направлено к центру `(400, 300)`. Гравитационная постоянная `G` и масса мяча берутся из `physics.cfg` игры (если файла нет, используются 500 и 1.0), масса дыры `M` приходит от пользователя. Мяч стартует в точке (80, 300). Вердикт: упал (расстояние до центра ≤ 10), оборот (накопленный угол вокруг дыры ≥ 360°) или улетел за пределы поля. В боте у поля нет верхней и нижней стенок, чтобы траектория была видна целиком.

**Сессии (stateless).** Всё про пользователя лежит в `sessions/<user_id>.json`, у каждого свой файл. Пример:

```json
{
  "screen_message_id": 122,
  "screen_chat_id": 7,
  "mass": 6.0,
  "subscribed": true,
  "runs": [
    {"mass": 6.0, "vx": 3.0, "vy": 1.0, "verdict": "orbit", "angle": 360.19}
  ]
}
```

Нет файла или он битый — создаётся новая сессия.

**Один экран.** Бот хранит `message_id` своего сообщения и правит его через `edit_message_text`. Ошибка `message is not modified` игнорируется, если сообщение удалено — бот отправляет новое.

**FSM.** Состояния: `menu`, `wait_mass`, `wait_vector`, `wait_file`. Они говорят боту, что сейчас ждать от пользователя.

**Проверка данных.** Масса от 0.1 до 1000, скорость от -20 до 20. В CSV проверяются: колонки, дата, имя (до 30 символов), счёт вида `5:3`, время — число от 0 до 24 часов. Файл должен быть `.csv`, до 1 МБ, в UTF-8. Битые строки пропускаются, одинаковые записи второй раз не добавляются.

**Логирование.** `bot_flight.log`: время, уровень, событие (старт, симуляции, загрузки, подписки, рассылки, ошибки).

## Формат выгрузки игры

`records.csv` пишет сама игра (ЛР 2): разделитель `;`, кодировка UTF-8 с BOM, чтобы Excel открывал без «кракозябр». Бот понимает и `;`, и `,`.

```
Дата;Имя;Счёт;Время партии, сек
2026-11-11 15:17:51;crework;5:0;38.8
```

Готовый пример для проверки: `example_records.csv`.
