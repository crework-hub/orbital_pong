# Orbital Pong — ядро на JavaScript (ЛР 4)

ЛР 4 «Алгоритмизация на языке JavaScript», вариант 15. Выполнил Гакуть М.А., группа 25-СТ.

Задание варианта: перенести гравитационное взаимодействие на JavaScript и обеспечить стабильность расчётов при малых `d`: добавить ограничение на максимальную силу (softening factor), чтобы мяч не получал бесконечное ускорение и не вылетал за экран.

Ядро ничего не рисует и не зависит от браузера: оно работает в Node.js и проверяется самопроверкой `selftest.js`. Рисование — тема ЛР 5 (папка `widget/`).

## Запуск

Нужен Node.js 18 или новее.

```bash
cd js_core
node selftest.js
```

Ожидаемый хвост вывода:

```
Всего проверок: 66
Успешно: 66
Провалено: 0

ВСЕ ПРОВЕРКИ ПРОШЛИ
```

## Формулы

В ЛР 1 сила была `F = G / d²`. В ядре добавлены масса дыры `M` и softening `ε`:

```
F = G · M / (d² + ε²)
a = F / m          (m — масса мяча)
ускорение направлено от мяча к центру дыры
vx += a · (center_x − x) / d
vy += a · (center_y − y) / d
```

| Величина | Значение | Откуда |
|---|---|---|
| `G` | 500 | `physics.cfg` |
| `m` | 1.0 | `physics.cfg` |
| `M` | 10 (по умолчанию) | `level.json`, поле `black_hole.mass` |
| `ε` | 6 | `config.js`, `SOFTENING` |
| радиус дыры | 10 | как в Python (`d > 10`) |

**Зачем softening.** При `d → 0` обычная формула даёт `F → ∞`: мяч получает огромную скорость за один кадр и вылетает за экран. Слагаемое `ε²` ограничивает силу: `F ≤ G · M / ε²`. Для `M = 10` это 138.9 (функция `MAX_FORCE` в `config.js`).

**Как выбрана ε.** При `d ≫ ε` формула почти не отличается от исходной: на `d = 100` разница 0.36%, а на `d = 10` (граница дыры) 26%. То есть softening заметен только у самой дыры. При `M = 1` и `ε = 0` формула в точности равна `G / d²` из ЛР 1 — это проверяет самопроверка.

**Порог срабатывания.** Мяч считается упавшим в дыру, если расстояние до центра ≤ 10. За кадр мяч может пролететь десятки пикселей и перескочить дыру целиком, поэтому проверяется не точка, а отрезок пути за кадр (`segmentHitsCircle`).

**Предел скорости.** Скорость мяча ограничена `MAX_BALL_SPEED = 30`. Это меньше суммы ширины ракетки и диаметра мяча (16 + 16 = 32), поэтому мяч не может пролететь сквозь ракетку между двумя кадрами.

## Конечный автомат

| Состояние | Что происходит | Переходы |
|---|---|---|
| `MENU` | ждём старта, шаги не считаются | → `PLAY` |
| `PLAY` | идёт партия | → `OVER` (кто-то набрал `win_score`), → `MENU` (перезапуск) |
| `OVER` | партия закончена | → `PLAY` (реванш), → `MENU` |

Запрещённые переходы (например, `MENU → OVER`) не выполняются: `go()` возвращает `false`. История переходов хранится в `StateMachine.history`.

## Правила партии в ядре

- Мяч отскакивает от верхней и нижней стены (`Field.bounceWalls`) и от ракеток (меняется знак `vx`).
- Мяч за левым или правым краем — гол, очко получает противоположная сторона.
- Дыра «съедает» мяч: очко получает соперник того, кто отбил мяч последним. Если мяч никто не отбивал (подача сразу упала в дыру), очков нет, подача повторяется. Это правило добавлено только в JS-версии (в Python мяч пролетает дыру насквозь); при очень большой массе (около 15 и больше) подача падает в дыру сразу.
- Партия идёт до `win_score` очков (по умолчанию 5).
- `Game.events` — «чёрный ящик» событий (`start`, `wall-bounce`, `paddle-hit`, `hole-catch`, `goal`, `game-over`), хранится не больше 200 штук.

## Загрузка уровня

`loadLevelFromText(text)` разбирает JSON в `try/catch`, затем `validateLevel` проверяет каждое обязательное поле (тип и диапазон). Для плохого поля берётся значение по умолчанию, ошибка попадает в список `errors`, игра не падает. Дыра вне поля переносится в центр.
